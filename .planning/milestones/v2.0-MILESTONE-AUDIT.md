## 1. Executive Summary

Milestone v2.0 for Cloud-Judge V2 has achieved complete implementation and end-to-end integration across all 7 architectural phases. Every defined requirement has been verified against working code, unit tests, integration suites, and production frontend bundles.

- **Sandbox & Execution:** Linux cgroup isolation, dropped capabilities, and multi-language compilation/runtime for C++, Python 3.12, and Java 21 (`SAND-01` through `SAND-04`).
- **Asynchronous Pipeline:** Redis queue broker, concurrent worker pool, and live per-test-case WebSocket streaming telemetry (`QUEUE-01` through `QUEUE-03`).
- **Linear Midnight Frontend:** Monaco editor with 3-pane resizable layout, distraction-free Zen mode, and interactive test runner (`IDE-01` through `IDE-04`).
- **Monetization & Subscriptions:** Dual payment gateways (Stripe & Razorpay) with automated webhook entitlement provisioning for Free vs. Pro tiers (`SUB-01` through `SUB-03`).
- **AI Assistant & Rate Limiting:** Gemini 2.5 Flash root-cause analysis and diff generation, guarded by Redis Token-Bucket rate limiting (`AI-01`, `AI-02`).
- **Contest Engine & Proctoring:** Timed ICPC competitions, O(log N) Redis Sorted Set leaderboards, fullscreen enforcement, and clipboard protection (`CONT-01` through `CONT-04`).
- **Plagiarism, Analytics & Ingress:** AST Winnowing similarity matrix generator, 21st.dev 3D isometric submission skyline heatmap, tumbling cube loader, and HAProxy Layer 7 reverse proxy (`PLAG-01`, `PLAG-02`, `ANL-01`, `ANL-02`, `PROXY-01`).

## 3. Cross-Phase Integration & End-to-End User Flows

1. **Submission & Execution Telemetry Flow (Phases 1 → 2 → 3):**
   - User types code in Monaco Editor and clicks "Run Code".
   - Client sends HTTP POST to `/api/v1/submissions`.
   - Gateway validates payload and enqueues to Redis channel `judge:submissions`.
   - Worker daemon claims job, mounts files, compiles and runs in Linux cgroup sandbox.
   - Per-test-case events (`compiling`, `test_case_start`, `test_case_end`) published via Redis Pub/Sub.
   - Gateway WebSocket broadcaster `/ws/submissions/{id}` streams events directly to `TestConsole.tsx`.
   - Verified end-to-end with 0 dropped events.

2. **Commercial Gating & Webhook Provisioning Flow (Phases 3 → 4 → 5):**
   - Free tier users trying to run >5 submissions/min receive HTTP 429 with `Retry-After`.
   - Free tier users attempting AI debug receive HTTP 403 with `upgrade_url: "/pricing"`.
   - User opens `UpgradeModal.tsx`, chooses Currency (USD via Stripe or INR via Razorpay).
   - Gateway initiates checkout session.
   - Provider sends webhook (`checkout.session.completed` or `payment.captured`).
   - Gateway verifies cryptographic signature, transitions entitlement store to `PRO`, and enables 100 sub/min + AI access immediately.

3. **Contest Experience & Anti-Cheat Flow (Phases 3 → 6):**
   - User enters timed contest; `App.tsx` activates contest header countdown and banner.
   - `useContestProctoring.ts` requests fullscreen and attaches event traps.
   - Attempts to exit fullscreen, blur tab, or copy/paste code trigger warning modals and register proctoring events on `/api/v1/contests/{id}/proctoring/event`.
   - Successful submissions update user score and calculate ICPC penalties (20 min per WA preceding AC).
   - Redis Sorted Set updates composite score `(solved * 10^9) - (penalty * 60)`.
   - `ContestLeaderboardModal.tsx` renders real-time rank updates.

4. **Post-Contest Audit & Visual Telemetry Flow (Phases 6 → 7):**
   - Contest organizer calls `/api/v1/plagiarism/contest/{id}/matrix`.
   - Plagiarism engine normalizes AST tokens across all submissions in Python, C++, and Java.
   - Winnowing algorithm computes fingerprint hashes and pairwise similarity scores.
   - Suspected submissions (>75% similarity) are flagged with matching line ranges.
   - Developer opens `DeveloperAnalyticsModal.tsx` to view activity on the 3D isometric skyline heatmap and execution indicators driven by the tumbling cube loader.

5. **Production Ingress Layer (Phase 7):**
   - HAProxy routes incoming traffic based on path and headers (`/ws/` to WebSocket backend, `/api/` and static traffic to gateway backend).
   - Tunnel timeouts configured to 1 hour for persistent WebSockets.
