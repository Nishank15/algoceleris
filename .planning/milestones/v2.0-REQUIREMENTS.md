# Requirements: Cloud-Judge V2

**Defined:** 2026-10-02
**Core Value:** Secure, ultra-low-latency, real-time multi-language code evaluation sandboxing paired with a frictionless developer experience and contest integrity.

## v1 Requirements

Requirements for initial release. Each maps to roadmap phases.

### Core Execution Sandbox

- [x] **SAND-01**: User submissions run inside isolated Linux cgroups with strict resource limits (256MB RAM, 1 CPU quota, network disabled)
- [x] **SAND-02**: Sandbox supports C++ compilation (gcc:latest) and execution with strict time limit (TLE) and memory limit (MLE) detection
- [x] **SAND-03**: Sandbox supports Python 3.12 execution within isolated cgroup environment
- [x] **SAND-04**: Sandbox supports Java 21 compilation and JVM execution with strict heap and cgroup boundaries

### Asynchronous Queue & Streaming Pipeline

- [x] **QUEUE-01**: FastAPI gateway accepts code submissions and enqueues jobs onto Redis broker with unique submission IDs
- [x] **QUEUE-02**: Worker daemon pool consumes jobs from Redis concurrently and evaluates against test case suites
- [x] **QUEUE-03**: User receives real-time live test case progress, execution status, and stdout/stderr over WebSockets

### Frontend IDE & Linear Design

- [x] **IDE-01**: User can edit code in Monaco Editor with syntax highlighting, autocomplete, and language selector (C++, Python, Java)
- [x] **IDE-02**: User can interact with a 3-pane resizable layout (Problem description, Monaco code editor, Test cases & console)
- [x] **IDE-03**: User can toggle between Normal mode and distraction-free Zen mode in a Linear-style midnight dark theme
- [x] **IDE-04**: User can run sample test cases interactively and view instant streaming output

### Commercial Subscriptions & Payments

- [x] **SUB-01**: User can view Free vs. Pro subscription tiers with distinct feature access matrix
- [x] **SUB-02**: User can upgrade to Pro via Stripe checkout session with automated webhook entitlement provisioning
- [x] **SUB-03**: User can upgrade to Pro via Razorpay payment gateway with verified signature and webhook fulfillment

### AI Debugging Assistant

- [x] **AI-01**: Pro user can request intelligent code fix suggestions and error explanations powered by Gemini 2.5 Flash
- [x] **AI-02**: AI assistant requests are enforced with Redis Token-Bucket rate limiting per user tier

### Contest Engine & Proctoring

- [x] **CONT-01**: User can participate in timed contests with problem sets and automated score calculation
- [x] **CONT-02**: User can view real-time contest leaderboards powered by Redis Sorted Sets with instant rank recalculation
- [x] **CONT-03**: Contest engine enforces fullscreen mode and displays warnings upon exit attempts
- [x] **CONT-04**: Contest view disables clipboard copy/paste actions to preserve contest integrity

### Plagiarism Detection

- [x] **PLAG-01**: Post-contest daemon extracts and normalizes Abstract Syntax Trees (AST) across all contest submissions
- [x] **PLAG-02**: Plagiarism engine detects code similarity and collusion using the Winnowing / MOSS fingerprinting algorithm and generates similarity matrices

### Developer Analytics & Visuals

- [x] **ANL-01**: User can view personal submission history and frequency on an interactive 3D isometric contribution heatmap
- [x] **ANL-02**: Platform displays a custom 3D isometric cube loader during execution waits and transitions

### Ingress & Load Balancing

- [x] **PROXY-01**: Ingress traffic is distributed across FastAPI gateway instances using an HAProxy Layer 7 reverse proxy configuration with WebSocket upgrade support

## v2 Requirements

Deferred to future release. Tracked but not in current roadmap.

### Collaboration & Advanced Proctoring

- **COLLAB-01**: Real-time multiplayer collaborative coding interview rooms
- **CUSTOM-01**: User-defined custom compiler flags and sandbox container image selection
- **AUDIO-01**: WebRTC webcam proctoring with automated face gaze tracking and acoustic anomaly detection

## Out of Scope

Explicitly excluded. Documented to prevent scope creep.

| Feature | Reason |
|---------|--------|
| Native mobile applications (iOS/Android) | Desktop/web IDE experience is the priority for code writing and multi-pane layout |
| Pod-per-submission Kubernetes runner | High startup latency overhead; Linux cgroups daemon workers chosen for sub-second start time |
| Manual human code review | Automated sandbox judge, AST plagiarism, and AI assistant handle evaluation |
