# Requirements: Cloud-Judge V2 (Milestone v2.2)

**Defined:** 2026-10-05
**Core Value:** Secure, ultra-low-latency, real-time multi-language code evaluation sandboxing paired with a frictionless developer experience and contest integrity.

## v2.2 Requirements

Requirements for Milestone v2.2: Production Identity, PostgreSQL Persistence, UX & Theme System.

### PostgreSQL Infrastructure & Alembic Migration Engine

- [x] **PG-01**: Docker Compose stack includes official `postgres:16-alpine` service with persistent named volume `postgres_data` and health checks.
- [x] **PG-02**: Gateway establishes asynchronous connection pooling using SQLAlchemy 2.0 and asyncpg with configurable pool sizes.
- [x] **PG-03**: Alembic migration engine initialized under `packages/gateway/alembic` with versioned, reproducible migration scripts.
- [x] **PG-04**: Relational schema defined for `users` (UUID PK, unique indexed username/email, password_hash, account_type, indexed optional college_name, avatar_url, timestamps).
- [x] **PG-05**: Relational schema defined for `subscriptions` (UUID PK, FK user_id, provider, customer_id, subscription_id, status, current_period_end).
- [x] **PG-06**: Relational schema defined for `submissions` (UUID PK, FK user_id nullable for guests, problem_slug, language, code, verdict, runtime_ms, memory_kb, testcases_passed, total_testcases, timestamps).
- [x] **PG-07**: Relational schema defined for `contest_participations` (UUID PK, FK user_id, contest_id, rank, score, penalty_minutes, rating_delta, timestamps).

### RedisBloom Uniqueness Layer & Hardened Authentication

- [x] **AUTH-01**: RedisBloom filter integration configured with sub-millisecond `BF.EXISTS` checks for username and email uniqueness.
- [x] **AUTH-02**: Dual-layer validation pipeline with Layer 1 Bloom filter pre-check and Layer 2 direct PostgreSQL fallback query.
- [x] **AUTH-03**: Startup/CLI seed script (`python -m src.cli seed-bloom`) to populate Bloom filters from existing DB records.
- [x] **AUTH-04**: Argon2id password hashing implemented with modern memory, time, and parallelism parameters.
- [x] **AUTH-05**: Dual-token authentication with 15-minute in-memory JWT Access Tokens and 7-30 day rotating Refresh Tokens stored in HttpOnly, SameSite=Strict, Secure cookies.
- [x] **AUTH-06**: `/api/v1/auth/refresh` endpoint providing silent token rotation with token family replay protection.
- [x] **AUTH-07**: Frontend `AuthContext` updated to cycle tokens, persist authenticated state, manage signup/login, and support guest bypass.

### Role-Based Access Control (RBAC) & Entitlements

- [x] **RBAC-01**: FastAPI dependency route guards `require_pro` and `require_admin` enforcing role-based endpoint permissions.
- [x] **RBAC-02**: Administrative CLI tool (`python -m src.cli set-role --email <email> --role <role>`) enabling role elevation without direct database access.
- [x] **RBAC-03**: Stripe and Razorpay webhook handlers synchronized with `subscriptions` table, updating `users.account_type` between `free` and `pro` on creation, cancellation, or lapse.

### Auth UX, Guest History Migration & DB-Backed Analytics

- [x] **UX-01**: Debounced (150ms) availability checks on `/auth/signup` providing instant Emerald (available) / Coral Red (taken) status badges.
- [x] **UX-02**: Automatic client-to-server guest submission migration reassigning anonymous localStorage submissions to the new account upon registration.
- [x] **UX-03**: Developer profile `/u/:username` difficulty solve breakdown ring calculated from distinct `ACCEPTED` submissions in PostgreSQL.
- [x] **UX-04**: Developer profile contest rating progression sparkline computed from `contest_participations` in PostgreSQL.
- [x] **UX-05**: 3D isometric contribution skyline driven by live daily submission aggregations from PostgreSQL.

### Linear Dark / Light Mode Toggle System

- [x] **THEME-01**: Full CSS token inversion system (Void/Carbon/Obsidian dark mode vs. Linear Light/subtle card/dark graphite light mode).
- [x] **THEME-02**: Sleek theme toggle button integrated in main `LinearHeaderNav`.
- [x] **THEME-03**: Monaco editor theme synchronization toggling between `linear-midnight` and `vs` (VS Code Light Modern).
- [x] **THEME-04**: Theme preference persisted in `localStorage` with fallback to system `prefers-color-scheme`.

## Future Requirements

### Real-Time Collaboration & Custom Sandboxes

- **COLLAB-01**: Real-time multiplayer collaborative coding interview rooms with live cursors and shared terminal.
- **SANDBOX-01**: User-defined custom compiler flags and sandbox container image selection.
- **PROCTOR-01**: WebRTC webcam proctoring with automated face gaze tracking and acoustic anomaly detection.

## Out of Scope

| Feature | Reason |
|---------|--------|
| Native mobile applications | Web application with responsive desktop focus is priority for IDE ergonomics |
| Dynamic Kubernetes pod-per-run orchestration | High latency overhead per run; Linux cgroups worker daemons deliver sub-second startup |
| Manual human code review | Automated judge evaluation, AST plagiarism detection, and Gemini AI assistant handle evaluation |
| OAuth social sign-in (Google/GitHub) | Deferred to future authentication hardening cycle; email/username + Argon2id is core for v2.2 |
