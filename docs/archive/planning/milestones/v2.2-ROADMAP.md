<summary>🟡 v2.2 Production Identity, PostgreSQL Persistence, UX & Theme System (Phases 13-17) — ACTIVE</summary>

- [x] **Phase 13: PostgreSQL Infrastructure & Alembic Migration Engine** (2/2 plans) — completed 2026-10-05
  - Goal: Add official `postgres:16-alpine` service, configure async SQLAlchemy/asyncpg pooling, initialize Alembic, and define core relational schemas (`users`, `subscriptions`, `submissions`, `contest_participations`).
  - Requirements: `PG-01`, `PG-02`, `PG-03`, `PG-04`, `PG-05`, `PG-06`, `PG-07`
  - Success Criteria:
    1. `postgres:16-alpine` running healthy in Docker Compose with named volume `postgres_data`.
    2. Gateway connects to PostgreSQL via asyncpg pool and executes health/readiness queries.
    3. Alembic migrations execute cleanly (`alembic upgrade head`) creating all 4 relational tables with UUID PKs and indexes.

- [x] **Phase 14: RedisBloom Uniqueness Layer & Hardened Authentication** (2/2 plans) — completed 2026-10-05
  - Goal: Build sub-millisecond username/email uniqueness validation via RedisBloom with DB fallback, seed CLI, Argon2id hashing, and dual-token auth (15m in-memory JWT + 7-30d HttpOnly rotating refresh token).
  - Requirements: `AUTH-01`, `AUTH-02`, `AUTH-03`, `AUTH-04`, `AUTH-05`, `AUTH-06`, `AUTH-07`
  - Success Criteria:
    1. RedisBloom filter checks `BF.EXISTS` in <1ms before falling back to PostgreSQL SELECT.
    2. CLI seed command `python -m src.cli seed-bloom` populates filters from DB records.
    3. Passwords hashed using Argon2id with modern parameters.
    4. Auth endpoints issue 15m in-memory access tokens and rotating HttpOnly refresh cookies with `/api/v1/auth/refresh` cycling tokens cleanly.
    5. Frontend `AuthContext` seamlessly maintains session and manages login/signup state.

- [x] **Phase 15: Role-Based Access Control (RBAC) & Entitlements** (2/2 plans) — completed 2026-10-05
  - Goal: Implement `require_pro` and `require_admin` FastAPI route guards, admin CLI role elevation, and automated Stripe/Razorpay webhook subscription synchronization.
  - Requirements: `RBAC-01`, `RBAC-02`, `RBAC-03`
  - Success Criteria:
    1. Routes protected by `require_pro` reject free accounts with 403 Forbidden.
    2. Admin CLI tool `python -m src.cli set-role` elevates user accounts safely without direct SQL queries.
    3. Stripe and Razorpay webhook handlers update `subscriptions` and elevate/demote `users.account_type` dynamically on subscription events.

- [x] **Phase 16: Auth UX, Guest History Migration & DB-Backed Analytics**
  - Goal: Deliver debounced signup availability badges, seamless client-to-server guest submission migration, and replace mock profile analytics with real PostgreSQL aggregations.
  - Requirements: `UX-01`, `UX-02`, `UX-03`, `UX-04`, `UX-05`
  - Success Criteria:
    1. Signup form renders debounced (150ms) Emerald/Coral Red badges for username/email availability.
    2. Anonymous submissions in localStorage automatically migrate and associate with the newly registered user on signup.
    3. Profile page `/u/:username` calculates difficulty solve breakdown rings and contest rating progressions from live PostgreSQL tables.
    4. 3D isometric skyline renders authentic daily submission activity aggregated from the database.

- [x] **Phase 17: Linear Dark / Light Mode Toggle System**
  - Goal: Deliver complete CSS token inversion (Midnight Dark vs. Linear Light), navigation toggle button, Monaco editor theme synchronization, and system preference persistence.
  - Requirements: `THEME-01`, `THEME-02`, `THEME-03`, `THEME-04`
  - Success Criteria:
    1. Entire application supports dark and light modes with harmonious token inversion.
    2. Sleek theme toggle button in `LinearHeaderNav` transitions themes instantly.
    3. Monaco editor synchronizes between `linear-midnight` and `vs` (VS Code Light Modern).
    4. Preference persists in `localStorage` and respects `prefers-color-scheme`.
