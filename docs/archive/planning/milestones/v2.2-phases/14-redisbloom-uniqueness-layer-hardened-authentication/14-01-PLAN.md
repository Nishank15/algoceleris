<task type="auto">
  <name>Task 2: Build RedisBloom Dual-Layer Uniqueness Checker</name>
  <files>packages/gateway/src/auth/bloom.py, packages/gateway/src/auth/__init__.py</files>
  <read_first>packages/gateway/src/database.py, packages/gateway/src/models/entities.py</read_first>
  <action>
Create `packages/gateway/src/auth/bloom.py`:
1. Define `BloomUniquenessChecker` class:
   - Constructor accepts `redis_client` (async or sync redis instance) or `redis_url`, plus optional `session_factory` for database fallback.
   - Filter keys: `bf:usernames` and `bf:emails`.
   - Method `async def ensure_filters_initialized()`:
     * Executes `BF.RESERVE bf:usernames 0.001 1000000` and `BF.RESERVE bf:emails 0.001 1000000`.
     * Catches and ignores "item exists" errors if already initialized.
   - Method `async def add_user(username: str, email: str) -> None`:
     * Executes `BF.ADD bf:usernames username.lower()` and `BF.ADD bf:emails email.lower()`.
   - Method `async def is_username_available(username: str, db_session: Optional[AsyncSession] = None) -> bool`:
     * Layer 1: Check `BF.EXISTS bf:usernames username.lower()`.
     * If 0, immediately return `True` (sub-millisecond fast path, 0% false negative rate).
     * If 1 (positive or false positive): Check Layer 2 in PostgreSQL:
       `SELECT 1 FROM users WHERE lower(username) = lower(:u) LIMIT 1`.
       If user exists in DB -> return `False` (taken).
       If user does NOT exist in DB -> return `True` (available, false positive absorbed).
   - Method `async def is_email_available(email: str, db_session: Optional[AsyncSession] = None) -> bool`:
     * Layer 1: Check `BF.EXISTS bf:emails email.lower()`.
     * If 0, immediately return `True`.
     * If 1, check Layer 2 in PostgreSQL:
       `SELECT 1 FROM users WHERE lower(email) = lower(:e) LIMIT 1`.
       If found -> return `False`, else return `True`.
2. Provide fallback in-memory bloom filter (`InMemoryBloomFilter` using bitsets or hash-based sets) if Redis client is not available or does not support BF commands, ensuring offline tests pass without a live Redis server.
3. Export `BloomUniquenessChecker` in `packages/gateway/src/auth/__init__.py`.
  </action>
  <verify>python3 -c "from packages.gateway.src.auth.bloom import BloomUniquenessChecker; print('Bloom module loaded successfully')"</verify>
  <acceptance_criteria>
    - packages/gateway/src/auth/bloom.py defines BloomUniquenessChecker
    - packages/gateway/src/auth/bloom.py implements BF.EXISTS check with PostgreSQL fallback
    - packages/gateway/src/auth/bloom.py provides in-memory fallback for testing

<task type="auto">
  <name>Task 3: Implement Argon2id Password Hashing & Dual-Token Engine</name>
  <files>packages/gateway/src/auth/security.py, packages/gateway/src/auth/__init__.py</files>
  <read_first>packages/gateway/src/auth/bloom.py</read_first>
  <action>
Create `packages/gateway/src/auth/security.py`:
1. Password Hashing:
   - Use `argon2.PasswordHasher(time_cost=2, memory_cost=65536, parallelism=1, hash_len=32, type=argon2.Type.ID)`.
   - Provide `hash_password(plain_password: str) -> str`.
   - Provide `verify_password(plain_password: str, hashed_password: str) -> bool`.
2. JWT Tokens:
   - Secret keys from environment: `JWT_SECRET_KEY` (default secure fallback for dev) and `JWT_ALGORITHM` ("HS256").
   - Access token lifetime: 15 minutes (`ACCESS_TOKEN_EXPIRE_MINUTES = 15`).
   - Refresh token lifetime: 14 days (`REFRESH_TOKEN_EXPIRE_DAYS = 14`).
   - `create_access_token(user_id: str, username: str, email: str, account_type: str = "free") -> str`:
     * Encodes `sub` (user_id), `username`, `email`, `role`, `exp`, `iat`, `type="access"`.
   - `create_refresh_token(user_id: str, family_id: Optional[str] = None) -> Tuple[str, str, str]`:
     * Generates `token_id` (uuid4), `family_id` (uuid4 or passed), and encodes `sub`, `jti` (token_id), `family` (family_id), `exp`, `type="refresh"`.
     * Returns `(token_str, token_id, family_id)`.
   - `decode_token(token_str: str) -> Dict[str, Any]`:
     * Decodes and validates signature and expiration.
3. Refresh Token Family Store in Redis:
   - `register_refresh_token(redis_client, token_id: str, family_id: str, user_id: str, ttl_seconds: int) -> None`:
     * Saves active token under key `auth:refresh:{token_id}`.
     * Records token in family set `auth:family:{family_id}`.
   - `validate_and_cycle_refresh_token(redis_client, token_id: str, family_id: str, user_id: str) -> Tuple[str, str]`:
     * Checks if `auth:refresh:{token_id}` exists.
     * If key is missing but `token_id` is in `auth:family:{family_id}` -> REPLAY DETECTED! Invalidate entire family (`auth:family:{family_id}`) and raise SecurityWarning/Exception.
     * If valid, delete old token `auth:refresh:{token_id}`, issue new refresh token in the same family, and register it.
4. Export security helpers in `packages/gateway/src/auth/__init__.py`.
  </action>
